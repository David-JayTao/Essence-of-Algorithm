solve(l, r) 做两件事：

    1. 求出 p[l ~ r] 这个点集内部的最近距离
    2. 把 p[l ~ r] 按 y 坐标排好序

p[] 这个数组在算法过程中，它的“排序意义”发生了变化：

一开始：p[1 ~ n] 按 x 排序
递归过程中：solve(l, r) 返回后，p[l ~ r] 被改成按 y 排序

这看起来很怪，但它是为了把合并阶段做到 O(n)。

PPT 里的伪代码也强调：递归函数返回最近距离，同时把当前区间按 y 排序；
临界区 Yd 不需要重新排序，只需要扫描一遍得到。

## 二六、能力型dp（上面多数为策略型dp）
### 鸡蛋掉落（蛋疼）
经过  2h 的战斗，总结如下：

#### 此题本质：能力型dp，二叉决策树

传统做法：

    f[k][n]=m,O(k*N^2,二分可至k*NlogN)，
    dp[k][n] = 1 + min_x max(dp[k - 1][x - 1], dp[k][n - x])

改用能力型状态定义：->反过来做，资本为k、m，能力为覆盖f[k][m]层楼（连续区间长度）
    
    f[k][m]=n

将求f[k][m]这个大问题进行拆分，通过已经解出的子问题合并得到大问题的解。
* 怎么划分大问题呢？
  
选择第一次仍的那个楼层作为分界点，f[k][m]=左区间+1+右区间，
    
    第一次扔的楼层是分界点。
    碎了，就进入左区间；没碎，就进入右区间。
    注意！！！！
    实际执行时只会走其中一个分支，
    但策略设计时必须保证两个分支都能处理。

* 怎么计算左右区间长度呢？
  
直接用状态定义来表示，
同时注意到：存在左区间是有前提的，就是在分界点这一层仍必须是碎了，才能在左区间去找F，
比如说分界点为0层，这一层不碎，就不存在左区间，只有右区间，
那么左区间最长有多长呢？f[k-1][m-1],

好，再算右区间，存在右区间的条件：分解点仍不会碎，才会继续往上查找F，f[k][m-1]。
所以，计算左右区间是相互独立并行的，不存在说右区间（没碎）在左区间（碎了）确定的floor的基础上+f[k][m-1]的说法，
    仅仅是用状态表示出子问题的数值是多少，两段区间相加罢了

* 刚好碰巧分界点的位置可以由左区间确定，右区间从这个分界点的上方开始继续拼接。

# 三、贪心
## 1、区间选点
数轴上选择尽量少的点，使得每个区间内至少包含一个选出的点。
## <=>最大不相交区间数量（活动选择问题）
在数轴上选择尽可能多的区间，使得选中的区间之间互不相交（包括端点）。
**法一、按左端点排序 + 动态收缩右边界**
* `st`、`ed` 记录当前的交集区间，随时更新；
* 包含加入的区间时，更新为新的最小完整交集区间
*  当不包含加入的区间时，结果加1，区间变为新区间
```
int cnt(vector<PII>&segs)
{   
    int res=0;
    int st=-2e9,ed=-2e9;
    for(auto seg:segs)
    {
        if(ed<seg.first)
        {
            res++;
            st=seg.first;//此行不更新也不影响结果
            ed=seg.second;
        }
        st=seg.first;//此行不更新也不影响结果
        if(seg.second<ed)ed=seg.second;
    }
    return res;
}
```

**法二、按右端点排序 + 遇到不包含的新区间时计数加一（每次选择最早结束的活动）**
![alt text](image-4.png)
### 1.1区间选点时的贪心证明
*(选择尽量少的点，使得每个区间内至少包含一个选出的点)*
* $Ans \le cnt$，显然；
* $Ans \ge cnt$，$cnt$ 个点覆盖了 $cnt$ 个独立的区间，想要覆盖所有的区间，则 $Ans \ge cnt$；

###  1.2最大不相交区间数量的贪心证明：
* 已找出 $cnt$ 个不相交的子区间，且这 $cnt$ 个区间的 $cnt$ 个右端点能覆盖所有区间，$Ans \ge cnt$，显然；
* 欲证 $Ans \le cnt$，**反证法**：
  * 假设 $Ans > cnt$，最多有 $Ans$ 个不相交子区间，至少要 $Ans$ 个点才能覆盖所有区间。
  * 这与仅需 $cnt$ 个点就可覆盖所有区间矛盾！
